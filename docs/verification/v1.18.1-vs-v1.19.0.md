## TL;DR

- Operational baseline (existing scenarios): **parity, zero regression**.
- v1.19.0 ships strictly more capability for ~1.4% lower compressed-token overhead in the same suite.
- New features (`smart_playbook`, `global_memory`, semantic re-rank, FS watcher, parser registry) are **net additive**; v1.18.1 has no equivalent so they're listed separately with mechanism-level evidence rather than cross-version numbers.

## 2. Capabilities exclusive to v1.19.0 (no v1.18.1 baseline possible)

These are listed with the mechanism that produces the saving, not a synthetic comparison.

### 2.1 `smart_playbook` — multi-step collapse

Example: built-in `ramp-up` playbook → 3 internal steps in 1 MCP call.

```
dryRun result (verified on v1.19.0):
  step 0  smart_status
  step 1  smart_doctor
  step 2  smart_search { query: "architecture decisions", kinds: ["adr"] }
  totalElapsedMs: 1 (dryRun)
```

Mechanism: every step the agent would otherwise dispatch costs at least one model round-trip (tool decision + tool response → next decision). Collapsing N steps into one call removes (N−1) round-trips. For the 5 built-ins:

| Playbook | Steps | Round-trips removed |
|---|---:|---:|
| `preflight-merge` | 3 | 2 |
| `debug-flake` | 3 | 2 |
| `refactor-safe` | 3 | 2 |
| `doc-sync` | 2 | 1 |
| `ramp-up` | 3 | 2 |

Conservative round-trip cost (Cursor / Claude MCP envelope + tool routing): 50–150 prompt tokens per skipped turn. v1.18.1 has no equivalent.

### 2.2 `smart_search` semantic re-rank

Opt-in via `semantic: true`. Cosine over hashing/TF-IDF embeddings, 256-dim Float32, < 5 ms per query on the sample-project fixture. Improves recall on vague queries where pure lexical search misses (synonyms, identifier casing). Pluggable `Embedder` interface ready to host ONNX/transformers.

v1.18.1: lexical only.

### 2.3 Reactive FS watcher

`fs.watch` native, 600 ms debounce, batched flush every 2 s. `smart_status.indexWatcher` exposes counters. Eliminates the "stale index after rename" failure mode where v1.18.1 needed an explicit `build_index` call between sessions.

### 2.4 Parser registry + Python/Go coverage (INDEX_VERSION 7)

New symbol kinds indexed:
- Python: decorators, `async def`, `TypeAlias`, `TypeVar`.
- Go: methods with receivers, `interface`, top-level `const`/`var`.

Direct consequence on `smart_review` and `smart_test affected`: more accurate callers graph → fewer false negatives in "what tests does this touch?".

### 2.5 `global_memory` — cross-project recall

`~/.devctx/global.db` (opt-in, `DEVCTX_GLOBAL_MEMORY=true`). Scrubs API keys, JWTs, PEM blocks, emails, home paths before persist. Project paths hashed (FNV-1a). Semantic recall reuses the same hashing embedder.

v1.18.1: each project is an island; decisions made in repo A are invisible to repo B.

## 3. Honest limitations of this report

- The orchestration suite was written before v1.19.0 features existed; it cannot show the upside of `smart_playbook`/`global_memory` natively. Adding playbook-aware scenarios would make the suite reflect the actual product surface and is queued as follow-up.
- Token costs of skipped round-trips depend on the MCP envelope of each client; figures above are conservative estimates, not measured per-client.
- Semantic re-rank quality should be measured with a recall@k eval (different harness). Currently only latency and correctness of the cosine path are verified.
